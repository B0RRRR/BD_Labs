# Система управления проектами — курсовой проект по дисциплине «Базы данных»

Информационная система на PostgreSQL 16 для компании, которая ведёт внутренние
и заказные проекты: команды, двухнедельные спринты с ограниченной ёмкостью,
задачи с жизненным циклом и историей статусов, обсуждения, метки, заказчики и договоры.
Проект развивает лабораторные работы № 1 и № 2 (каталоги `Lab1/`, `Lab2/`).

Пояснительная записка — `Note/Пояснительная_записка.pdf`.

## Развёртывание

Нужны PostgreSQL 16 и `psql`. Подключение задаётся стандартными переменными
`PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`.

```bash
createdb project_mgmt
export PGDATABASE=project_mgmt
export APP_DB_PASSWORD='придумайте пароль'   # пароль роли приложения pm_app
db/init.sh                                    # SEED_DEMO=0 — без демонстрационных данных
```

Пароли в репозитории не хранятся: пример переменных — `.env.example`,
собственный `.env` в git не попадает.

Порядок развёртывания: миграции 001–004 (схема лабораторных работ) → контрольные данные →
миграции 005–011 (миграция 005 меняет структуру заполненной базы и переносит данные) →
демонстрационные данные.

## Демонстрация

```bash
# запросы и отчёты на дату 14.11.2026
psql -v today=2026-11-14 -f db/queries/queries.sql
psql -v today=2026-11-14 -f db/queries/reports.sql

# пакетная загрузка: 5 строк загружаются, 7 отклоняются с причиной
psql -v file=db/import/tasks_sample.csv -f db/import/import_tasks.sql

# проверки на копии базы: createdb -T project_mgmt pm_demo
psql -d pm_demo -f db/demo/constraints.sql   # 17 ожидаемых ошибок
psql -d pm_demo -f db/demo/scenario.sql      # история 6 переходов, аудит
psql -d pm_demo -f db/demo/transactions.sql  # успех и полный откат

# конкурентный доступ: аномалия без блокировки, защита FOR UPDATE, SERIALIZABLE с повтором
db/demo/concurrency.sh

# производительность: отдельная база с 100 000 задач
createdb pm_perf && PGDATABASE=pm_perf SEED_DEMO=0 db/init.sh
psql -d pm_perf -v n_tasks=100000 -f db/perf/load_data.sql
python3 db/perf/bench.py pm_perf
```

## Бизнес-правила, которые обеспечивает СУБД

- исполнитель задачи — участник её проекта; при исключении участника его задачи становятся неназначенными (составной FK);
- задача входит только в спринт своего проекта и только оценённой; сумма оценок задач спринта не превышает его ёмкость (триггер с блокировкой строки спринта);
- спринты проекта не пересекаются по времени, активный спринт у проекта один (EXCLUDE, частичный уникальный индекс);
- статус задачи меняется только по жизненному циклу `todo → in_progress → review → done`, взять в работу можно только назначенную задачу; момент завершения ставится автоматически;
- договор есть только у проекта с заказчиком и заключён именно с ним; у проекта не более одного договора (1:1);
- каждая смена статуса попадает в историю, изменения проектов, задач и договоров — в журнал аудита.

Собственные коды ошибок: `PM001` — недопустимый переход статуса, `PM002` — задача не
назначена, `PM003` — недопустимое состояние спринта, `PM004` — превышена ёмкость спринта,
`PM005` — договор без заказчика.
